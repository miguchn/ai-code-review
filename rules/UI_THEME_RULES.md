# AI Code Review 智能代码审查平台 UI 主题规则

> 状态：主题设计基线  
> 适用范围：`acr-ui` 后续新增、改版和 UI 审查工作  
> 视觉基线：`src/views/login.vue`、`src/assets/images/login-light.png`  
> 当前主题：仅浅色主题  
> 约束：本文提供设计变量建议，不代表已写入 CSS；落地时应按实际组件库能力映射。

## 1. 规则目标与使用方式

本规则用于统一 AI Code Review 智能代码审查平台的页面、组件和代码审核业务界面。新增页面必须遵守；已有页面在业务改版或组件被实际触及时按本规则局部收敛，不为统一主题单独扩大重构范围。

当前登录页是品牌方向基线，不是所有系统页面的版式模板：

- 继承可信绿色、冷灰文字、浅绿灰背景、清晰留白、轻边框和低强度阴影。
- 继承 `login-light.png` 中“代码、检查、保护、风险提示”的业务语义。
- 登录页的 20px 大圆角、半透明卡片、柔和渐变和插图氛围仅属于登录/品牌展示场景，不应成为后台页面默认样式。
- 不继承插图中的机器人、发光粒子、光环或复杂机械造型；后续插图应进一步抽象和克制。
- 不调整现有登录页。本文与登录页存在局部差异时，登录页保持现状，系统新增页面以本文为准。

## 2. 设计原则

### 2.1 核心原则

1. **内容优先**：审查结论、代码差异、风险等级和操作路径始终高于装饰。
2. **专业可信**：绿色表达可信、通过和可执行操作，不表达娱乐、社交或促销氛围。
3. **克制分层**：优先通过背景明度、1px 边框和少量阴影区分层级。
4. **高密度但不拥挤**：表格和代码区保持效率；表单、卡片和页面留出稳定呼吸空间。
5. **一致胜于新奇**：同一语义必须使用同一颜色、字号、圆角和状态反馈。
6. **技术感来自信息结构**：通过等宽字体、代码语法、清晰路径和准确状态体现技术属性，不堆叠“科技”装饰。
7. **状态不只依赖颜色**：风险、成功和错误必须同时使用文字、图标或形状标识。
8. **可访问性优先**：普通正文与背景对比度目标不低于 4.5:1；键盘焦点清晰可见；不可用状态仍须可辨认。

### 2.2 风格关键词

现代、克制、清晰、专业、轻量、可信、冷静、精确、研发友好、低装饰。

## 3. 品牌视觉定位

品牌绿色源自登录页 `#16A34A`，含义为“审查通过、可信交付、持续改进”。视觉上应偏沉稳自然绿，不向荧光绿、黄绿或即时通信类鲜亮绿偏移。

品牌视觉的表达顺序：

1. 产品名称、主操作和当前选中状态；
2. 关键图标、链接和有限的品牌识别元素；
3. 柔和品牌背景与边框；
4. 装饰性绿色仅作为补充，不得与内容竞争。

同一屏幕内，品牌实色填充原则上只保留给一个主操作或一个最主要的选中对象。成功状态虽同属绿色系，但默认使用浅背景、语义图标和文字，不与主按钮争夺视觉层级。

## 4. 颜色变量建议

以下变量名用于说明语义，可在后续主题工程中映射为 CSS 变量、Element Plus 变量或设计 Token。本次不写入代码。

### 4.1 品牌绿色

| 建议变量 | HEX | 用途 |
| --- | --- | --- |
| `brand-500` | `#16A34A` | 主品牌色；品牌文字、重点图标、复选选中、非实底强调 |
| `brand-600` | `#15803D` | 高对比品牌色；主按钮默认、正文中的品牌链接 |
| `brand-700` | `#166534` | Hover、较强文字强调 |
| `brand-800` | `#14532D` | Active、按下状态，避免大面积使用 |
| `brand-bg-soft` | `#EAF7EE` | 品牌浅背景、轻提示、筛选选中背景 |
| `brand-bg-selected` | `#E2F4E7` | 明确选中项、当前行或当前导航项 |
| `brand-border` | `#BCE7C8` | 品牌轻边框、选中态边框 |
| `brand-icon` | `#16843F` | 浅背景上的品牌图标 |
| `brand-text` | `#166534` | 浅品牌背景上的文字 |
| `brand-on-solid` | `#F8FBF9` | 深品牌实底上的文字和图标 |

使用规则：

- `#16A34A` 是主品牌识别色，但不直接作为承载小号浅色文字的按钮底色。
- 主按钮使用 `#15803D`，以保证 `#F8FBF9` 文字具有足够对比度。
- 主按钮 Hover 使用 `#166534`，Active 使用 `#14532D`。
- 品牌色不用于整页背景、大面积表头、长段正文或大块代码背景。
- 品牌色与状态色同时出现时，主操作可用实色品牌绿；状态使用浅底标签或图标。

### 4.2 状态颜色

| 状态 | 文字 | 图标 | 浅背景 | 边框 | 使用规则 |
| --- | --- | --- | --- | --- | --- |
| 成功 | `#2F7650` | `#3D8B61` | `#F0F7F2` | `#CFE5D5` | 审核通过、已修复；默认不使用大面积实绿 |
| 警告 | `#946200` | `#B7791F` | `#FFF8E6` | `#F0D6A0` | 风险、需关注、等待处理 |
| 错误 | `#C2413A` | `#C2413A` | `#FFF1F0` | `#F2C4C1` | 严重问题、校验失败、危险操作 |
| 信息 | `#3F6F8F` | `#4F7F9D` | `#EEF6FA` | `#C9DFEA` | 建议优化、审核中、普通提示 |
| 禁用 | `#7E8B84` | `#8E9A94` | `#EFF2F0` | `#D5DDD8` | 不可操作、不可编辑、过期内容 |

状态色必须遵守：

- 状态标签采用“浅背景 + 深文字 + 可选图标”，不默认采用高饱和实色底。
- 错误色只用于错误、破坏性操作和严重风险，不用于一般提醒。
- 警告文案使用 `#946200`；较亮的 `#B7791F` 仅作图标或较大图形，不作小号正文。
- 成功状态与品牌绿通过语义、明度和承载方式区分：成功偏灰绿且以浅底呈现，品牌绿承担主要交互。
- 信息色保持低饱和蓝灰，不演变为传统深蓝后台主题。

### 4.3 中性色

| 建议变量 | HEX / RGBA | 用途 |
| --- | --- | --- |
| `neutral-page` | `#F5F7F6` | 全局页面背景 |
| `neutral-content` | `#F8FAF9` | 主内容区域、分区背景 |
| `neutral-card` | `#FCFDFC` | 普通卡片、表单面板 |
| `neutral-overlay` | `#FEFFFE` | 弹窗、抽屉、下拉菜单 |
| `neutral-code` | `#F6F8F7` | 浅色代码区、Diff 基础背景 |
| `text-primary` | `#0F172A` | 一级标题、核心数据 |
| `text-regular` | `#334155` | 正文、表单文字、表格主体 |
| `text-secondary` | `#64748B` | 二级说明、次要信息 |
| `text-assist` | `#7E8B84` | 辅助信息、时间、元数据 |
| `text-placeholder` | `#94A3B8` | 输入占位符；不得承载必要信息 |
| `text-disabled` | `#8E9A94` | 禁用文字 |
| `border-default` | `#D8E0DC` | 输入框、普通卡片、控件边框 |
| `border-light` | `#E5EAE7` | 表格行、弱分区边界 |
| `divider` | `#EBEFED` | 分割线 |
| `bg-hover` | `#F0F4F1` | 中性 Hover |
| `bg-selected` | `#EAF7EE` | 品牌相关选中 |
| `mask` | `rgba(15, 23, 42, 0.42)` | 模态遮罩 |

中性色规则：

- 不使用 `#000000` 作为正文，不使用 `#FFFFFF` 作为大面积页面底色。
- 接近白色的 `#FEFFFE` 只用于需要抬高层级的浮层。
- 分割线能用间距表达时不画线；必须使用时仅用 1px 低对比边界。
- `text-placeholder` 只用于提示，不用于标签、默认值或必要说明。

## 5. 页面层级规则

| 层级 | 背景与边界 | 阴影 | 典型对象 |
| --- | --- | --- | --- |
| L0 全局画布 | `neutral-page` | 无 | 应用整体背景 |
| L1 主内容区 | 透明或 `neutral-content` | 无 | 页面内容容器、工作区 |
| L2 内容表面 | `neutral-card` + 1px `border-default` | 默认无 | 卡片、查询区、表格容器 |
| L3 局部悬浮 | `neutral-overlay` + 1px `border-light` | 轻阴影 | Sticky 工具栏、浮动操作条 |
| L4 菜单浮层 | `neutral-overlay` + 1px `border-light` | 中阴影 | 下拉菜单、Popover、日期面板 |
| L5 模态层 | `neutral-overlay` + 遮罩 | 强阴影 | 弹窗、重要确认 |

具体规则：

- 页面主内容不通过整块品牌色或深色背景建立层级。
- 普通卡片和表格优先靠边框与背景差异分层，不加明显阴影。
- 弹窗高于抽屉内容；下拉菜单高于当前表面，但不高于模态层。
- 抽屉使用右侧或左侧边界及中等阴影，背景仍为浅色。
- 表格与表单可直接放在同一内容表面，不为每个字段或每组按钮再嵌套卡片。
- 代码内容区使用独立浅灰背景和轻边框，不使用整块绿色背景。

## 6. 字体与文字层级

### 6.1 字体族

不引入额外字体依赖，沿用系统字体，建议顺序：

`-apple-system, BlinkMacSystemFont, "SF Pro Text", "Segoe UI", Roboto, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Helvetica Neue", Arial, sans-serif`

代码、分支名、提交号、仓库名、文件路径和需要等宽对齐的数字使用：

`ui-monospace, SFMono-Regular, Menlo, Monaco, Consolas, "Liberation Mono", "Courier New", monospace`

### 6.2 文字层级

| 角色 | 字号 | 字重 | 行高 | 字间距 | 颜色 |
| --- | ---: | ---: | ---: | ---: | --- |
| 页面主标题 | 24px | 600 | 32px | `-0.01em` | `text-primary` |
| 模块标题 | 18px | 600 | 26px | `-0.005em` | `text-primary` |
| 卡片标题 | 15–16px | 600 | 24px | 0 | `text-primary` |
| 正文 | 14px | 400 | 22px | 0 | `text-regular` |
| 辅助说明 | 13px | 400 | 20px | 0 | `text-secondary` |
| 标签文字 | 12px | 500 | 18px | `0.01em` | 按语义 |
| 表格表头 | 12px | 600 | 18px | `0.01em` | `text-secondary` |
| 表格正文 | 13px | 400 | 20px | 0 | `text-regular` |
| 表单标签 | 13px | 500 | 20px | 0 | `text-regular` |
| 表单输入 | 14px | 400 | 22px | 0 | `text-primary` |
| 数字指标 | 28px | 600–650 | 34px | `-0.015em` | `text-primary` |
| 代码与文件名 | 13px | 400–500 | 20px | 0 | `#24302A` |
| 行号与代码元数据 | 12px | 400 | 20px | 0 | `text-assist` |

文字使用规则：

- 正文只使用 400 或 500；标题主要使用 600。避免通过大量 700/800 字重制造层级。
- 登录页品牌展示的大字号和较高字重不复制到后台内容页。
- 中文和英文混排时不额外放大 `AI`、`Code Review`；产品名整体保持自然。
- 分支名、提交号、文件名和路径使用等宽字体，但不使用高饱和颜色或额外粗体。
- 数字指标使用等宽数字特性（tabular numbers）；单位采用 12–14px 次级文字。
- 链接必须通过颜色和 Hover/Focus 反馈可识别，正文内链接建议加下划线或在 Hover 时显示下划线。
- 单行标题超长时省略并提供完整内容提示；审查结论和错误信息不得无提示截断。

## 7. 间距规则

采用 4px 基础网格，允许的常用间距为：

| Token | 值 | 典型用途 |
| --- | ---: | --- |
| `space-1` | 4px | 图标与极短辅助信息 |
| `space-2` | 8px | 图标与文字、紧凑控件 |
| `space-3` | 12px | 表单内部、标签组 |
| `space-4` | 16px | 标准组件间距、卡片内部紧凑区 |
| `space-5` | 20px | 卡片标准内边距 |
| `space-6` | 24px | 页面区块、普通卡片内边距 |
| `space-8` | 32px | 页面主要区块间距 |
| `space-10` | 40px | 大区块分隔 |
| `space-12` | 48px | 页面一级内容分组 |
| `space-16` | 64px | 少量品牌展示留白 |

应用规则：

- 页面标题与首个内容区：24px。
- 同级卡片间距：16–20px；密集数据区可用 12px，但不得更小。
- 普通卡片内边距：20–24px；紧凑表格容器可由表格自身控制，不重复叠加。
- 表单项垂直间距：16px；同一行字段水平间距：16px。
- 标签与标签之间：6–8px。
- 表格单元格水平内边距：12–16px；行高以 44–48px 为主。
- 不使用 5px、7px、13px 等无规则间距修补布局。

## 8. 圆角规则

| 层级 | 圆角 | 对象 |
| --- | ---: | --- |
| 小圆角 | 4–6px | 状态标签、代码标记、行内提示 |
| 控件圆角 | 8px | 输入框、按钮、选择器、图标按钮 |
| 卡片圆角 | 12px | 普通卡片、表格容器、操作面板 |
| 浮层圆角 | 12–14px | 下拉菜单、Popover、弹窗、抽屉局部卡片 |
| 展示圆角 | 16px | 少量大型空状态或品牌展示区域 |
| 登录页例外 | 20px | 仅保留现有登录卡片，不向系统页面扩散 |

规则：

- 标签默认不是胶囊形；只有人数、计数、开关类短内容可使用全圆角。
- 圆形只用于头像、状态点和单一图标按钮。
- 同一容器内嵌套表面应逐级减小圆角，避免多层同半径“套娃”。

## 9. 阴影与边框规则

### 9.1 建议阴影

| 名称 | 阴影 | 用途 |
| --- | --- | --- |
| 无阴影 | `none` | 普通卡片、表格、表单 |
| 轻阴影 | `0 4px 16px rgba(15, 23, 42, 0.06)` | Sticky 工具条、轻悬浮卡片 |
| 中阴影 | `0 10px 30px rgba(15, 23, 42, 0.10)` | 下拉菜单、Popover |
| 强阴影 | `0 20px 56px rgba(15, 23, 42, 0.16)` | 弹窗 |
| 抽屉阴影 | `-12px 0 36px rgba(15, 23, 42, 0.10)` | 右侧抽屉；左侧方向相反 |

### 9.2 边框规则

- 普通边框统一 1px，不使用深色粗边框。
- 卡片使用 `border-default`；内部弱分隔使用 `border-light` 或 `divider`。
- Hover 不通过加粗边框实现，避免布局抖动。
- Focus 外描边不占布局空间。
- 不同时叠加高对比边框、明显阴影和强调背景；同一对象最多选择两种层级手段。

## 10. 组件规则

### 10.1 按钮

标准高度：

- 小型：28px，仅用于表格内紧凑操作。
- 默认：36px，系统页面首选。
- 大型：40px，用于关键表单或空状态。
- 登录页现有 42px 按钮为局部例外。

按钮水平内边距为 12–16px，文字 14px/500–600，圆角 8px。按钮不使用渐变、发光或复杂位移动效。

| 类型 | 默认 | Hover | Active | Disabled |
| --- | --- | --- | --- | --- |
| 主按钮 | `#15803D` 实底，`#F8FBF9` 文字 | `#166534` | `#14532D` | `#D5DED8` 底，`#7E8B84` 文字 |
| 次按钮 | `neutral-card`，`border-default` | `bg-hover`，边框 `#AFC0B6` | `#E8EDEA` | `#F2F4F3`，`border-light` |
| 文字按钮 | `brand-600` 文字，透明底 | `brand-bg-soft` | `brand-bg-selected` | `text-disabled` |
| 危险按钮 | `#B93832` 实底或浅底描边 | `#A6312C` | `#8F2B27` | 中性禁用样式 |
| 图标按钮 | 32–36px 方形，中性图标 | `bg-hover` | `#E8EDEA` | 中性禁用样式 |

所有按钮状态：

- Focus Visible：`#16A34A` 边界，并使用 `0 0 0 3px rgba(22, 163, 74, 0.16)` 外描边。
- Loading：保持按钮原宽度，禁用重复提交；显示静态加载图标或“处理中…”文本，不使用持续旋转、流光或呼吸动画。
- 图标按钮必须有可访问名称；只有图标且语义不明显时提供 Tooltip。
- 同一操作区只保留一个主按钮；“取消”一般使用次按钮，不使用危险色。

### 10.2 表单

输入框、选择器、日期控件、搜索框和文本域统一：

- 默认高度 36px；重要或独立表单可用 40px。
- 背景 `neutral-card`，边框 `border-default`，圆角 8px。
- 输入文字 14px，前后图标 16–18px。
- 多行文本域最小高度 96px，内边距 10–12px。
- 搜索框可带搜索图标，但默认不使用胶囊形。

| 状态 | 视觉规则 |
| --- | --- |
| Default | 1px `border-default`，`neutral-card` 背景 |
| Hover | 边框 `#AFC0B6`，不加阴影 |
| Focus | 边框 `#16A34A` + `0 0 0 3px rgba(22, 163, 74, 0.14)` |
| Error | 边框 `#C2413A` + `0 0 0 3px rgba(194, 65, 58, 0.10)`；错误文字置于字段下方 |
| Disabled | `#EFF2F0` 背景，`#D5DDD8` 边框，`text-disabled` 文字 |
| Readonly | `#F7F9F8` 背景，保留正常文字对比度；无 Hover/Focus 编辑暗示 |

表单规则：

- 标签置于输入框上方或同一表单统一左侧，不混用。
- 必填标记使用小型错误色星号，但不替代文字说明。
- 校验发生后保留字段高度，避免页面跳动。
- 只读与禁用必须可区分：只读内容仍可选择和复制；禁用内容不可操作。
- 浏览器自动填充后的背景和文字必须仍符合浅色主题。

### 10.3 标签、徽标与状态点

- 标签高度 22–24px，水平内边距 6–8px，圆角 4–6px，字号 12px/500。
- 普通分类标签用中性背景；品牌标签只标识当前选择或产品属性。
- 状态标签按状态色表使用浅背景和深文字。
- 状态点直径 6–8px，必须配文字，不单独承担语义。
- 同一对象标签超过 3 个时优先折叠为“+N”，避免彩色标签墙。

### 10.4 卡片

所有卡片默认使用 `neutral-card`、1px `border-default`、12px 圆角、20–24px 内边距，无阴影。

| 卡片类型 | 规则 |
| --- | --- |
| 普通信息卡片 | 中性表面；标题、正文、操作清晰分区 |
| 数据指标卡片 | 数字为第一视觉层级；最多一个低饱和趋势色，不使用渐变底 |
| 操作卡片 | 操作区靠右或底部；只保留一个主操作 |
| 风险提示卡片 | 语义图标 + 2–3px 左侧色条或浅色标题区；禁止整卡高饱和填充 |
| 代码审核结果卡片 | 结论、风险数量、关键文件和下一步操作依次呈现 |
| 问题详情卡片 | 风险等级、位置、原因、建议、处理状态固定顺序 |

卡片禁止：

- 每张卡使用不同主题色；
- 默认悬浮位移；
- 多层渐变、装饰光斑和无意义插图；
- 卡片内部继续嵌套多个同样式卡片。

### 10.5 表格

- 表头背景使用 `neutral-content` 或与表格主体同色，仅靠字重和底边界区分。
- 表头 12px/600、`text-secondary`；正文 13px/400、`text-regular`。
- 默认行高 44–48px；代码路径或双行信息可增至 56px。
- 只保留水平分隔线，不使用完整网格和竖向分割线。
- Row Hover 使用 `bg-hover`；选中行使用 `bg-selected`，并保留复选或选中图标。
- 斑马纹默认关闭；确有超宽、长列表可使用极弱交替背景。
- 固定列与主体之间使用 8–12px 渐隐阴影，不使用深色竖线。
- 操作列右对齐，优先展示 1–2 个高频文字/图标操作，其余收进菜单。
- 分页与表格间距 16px；当前页使用品牌选中态，不使用实色胶囊堆叠。
- 空状态包含简洁图标、原因说明和最多一个主操作，不用大幅插图填满表格。
- 宽表格必须在容器内横向滚动；不得压缩到文字无法阅读或让页面整体横向溢出。

### 10.6 弹窗、抽屉、下拉菜单与浮层

- 弹窗圆角 14px，内边距 24px，标题 18px/600；危险确认明确说明对象与影响。
- 抽屉用于上下文详情和长表单，不用于所有编辑操作；宽度应随视口限制，不能写死超出小屏。
- 下拉菜单项高度 32–36px，左右内边距 12px，Hover 使用 `bg-hover`。
- Popover 与 Tooltip 内容短而明确；Tooltip 不承载关键业务流程。
- 模态遮罩使用 `mask`，不叠加模糊或彩色滤镜。

### 10.7 导航、筛选与空状态

- 当前导航项使用品牌文字、浅品牌背景或 2px 品牌指示线，最多使用其中两种。
- 侧栏保持浅色或中性表面，不使用传统深蓝底。
- 筛选区优先使用紧凑表单布局；高级筛选折叠，不将每个筛选项做成彩色胶囊。
- Breadcrumb、仓库路径和页面上下文使用 `text-secondary`；当前层级使用 `text-regular`。
- 空状态插图控制在内容区的 20%–30%，优先使用线性图标和简短说明。

## 11. 代码审核业务场景规则

### 11.1 审核状态

| 业务状态 | 视觉语义 | 推荐呈现 |
| --- | --- | --- |
| 审核通过 | 成功 | 成功图标 + “审核通过”浅成功标签 |
| 存在风险 | 警告 | 警告图标 + 风险数量；不等同于严重错误 |
| 建议优化 | 信息 | 信息图标 + 蓝灰浅底标签 |
| 严重问题 | 错误 | 错误图标 + 明确等级与问题数量 |
| 待确认 | 中性/警告 | 中性标签；临近超时或阻塞时升级为警告 |
| 已忽略 | 中性 | 灰色标签 + 忽略原因入口，降低视觉权重 |
| 已修复 | 成功 | 成功标签 + 修复提交或验证结果 |
| 审核中 | 信息 | 信息标签 + 静态进度文本或确定性进度条 |

状态变更后应保留文字反馈；不得只通过标签颜色变化表示。状态排序以业务风险和待办优先级为准，不按颜色深浅排序。

### 11.2 风险等级

| 等级 | 颜色 | 规则 |
| --- | --- | --- |
| 严重 / Critical | 错误 | 必须带等级文字和错误图标；可使用 3px 左侧错误色条 |
| 高 / High | 错误 | 使用浅错误底，不使用整卡红色 |
| 中 / Medium | 警告 | 使用浅警告底 |
| 低 / Low | 信息 | 使用浅信息底 |
| 未定 / Unrated | 中性 | 必须标明“未定级”，不能留空冒充低风险 |

### 11.3 代码差异

代码差异区以可读性为第一优先级，不因品牌主题将代码大面积染绿。

| 内容 | 背景 | 边界/强调 | 文字 |
| --- | --- | --- | --- |
| 代码基础区 | `#F6F8F7` | `border-light` | `#24302A` |
| 新增代码 | `#EAF6ED` | 行号区 `#D2EAD8` | 保持语法色；`+` 使用 `#2F7650` |
| 删除代码 | `#FCEDEC` | 行号区 `#F3D2CF` | 保持语法色；`-` 使用 `#C2413A` |
| 修改/关注 | `#FFF7E6` | 行号区 `#F1DDAF` | `#5C4A22` |
| 当前定位 | `#EEF6FA` | 2px `#4F7F9D` 指示线 | 正常代码文字 |
| 行号 | 与代码区相邻的稍深浅灰 | 右侧 1px 弱边界 | `text-assist` |

代码规则：

- 新增和删除必须同时显示 `+` / `-`、行号或其他非颜色标识。
- 语法高亮使用低饱和蓝、紫、棕、青等常规代码色；绿色不独占所有 Token。
- 代码正文 13px/20px，长行保持横向滚动，不默认强制换行。
- 文件路径显示仓库相对路径；路径中目录使用 `text-secondary`，文件名可用 `text-regular` 或 500 字重。
- 文件头固定展示文件状态、变更行数和展开/折叠操作。
- 大 Diff 默认按文件分组并允许折叠；折叠状态必须保留问题数量。

### 11.4 问题定位与建议

- 问题定位必须包含文件路径、起止行号、风险等级和可跳转操作。
- AI 建议使用中性卡片或 `brand-bg-soft` 的轻提示区，可加 2px 品牌色左边界；不得使用渐变、AI 星芒或发光头像。
- 人工审核意见使用中性表面，展示审核人、时间和身份；不得用另一套高饱和颜色与 AI 建议对抗。
- AI 内容与人工内容必须有清晰文字来源标识，不能仅靠图标或颜色区分。
- 建议中代码片段遵循代码区规范；可执行修复必须明确影响范围并由用户确认。
- 严重问题的原因、影响和修复建议按固定顺序展示，避免只显示模型结论。

## 12. 图标与插图规则

### 12.1 图标

- 全站只使用一套主要图标风格；线性或轻量面性二选一，以项目现有图标体系为先。
- 常规图标 16px，页面操作 18px，空状态 32–48px。
- 线性图标建议线宽 1.5–2px，端点和转角风格统一。
- 默认图标使用 `text-secondary`；Hover 或当前项使用品牌色；语义图标按状态色。
- 不混用 3D、拟物、发光、手绘和不同线宽图标。

### 12.2 插图

从 `login-light.png` 仅延续以下方向：

- 代码窗口、审核勾选、保护盾牌、问题提示等业务符号；
- 绿色可信感与冷静的浅色构图；
- 清晰主体、有限元素和专业语义。

后续插图必须：

- 使用抽象几何、简洁线面和低饱和配色；
- 与真实业务空状态或说明内容相关；
- 控制装饰数量，不干扰标题和操作。

后续插图禁止：

- 机器人、机械大脑、虚拟人物、芯片电路、数据流；
- 星芒、粒子、光环、蓝紫霓虹和大面积发光；
- 漂浮界面堆叠、复杂机械结构和无业务含义的“AI 感”装饰；
- 直接复制、裁切复用登录页插图中的机器人或构图。

## 13. 动效规则

| 场景 | 时长 | 建议 |
| --- | ---: | --- |
| Hover / Press | 120–160ms | 颜色、背景或边框轻微变化 |
| 展开 / 收起 | 160–200ms | 高度/透明度变化，位移不超过 4px |
| 浮层进入 | 160–200ms | 透明度 + 2–4px 位移 |
| 页面局部切换 | 180–240ms | 轻微淡入，不做整页大幅移动 |
| 状态变化 | 160–220ms | 背景或图标一次性过渡 |

规则：

- 使用稳定缓动，如 `ease-out` 或接近 `cubic-bezier(0.2, 0, 0, 1)`。
- 不使用弹跳、旋转、流光、视差和持续循环动画。
- Loading 优先确定性进度条、静态骨架、占位或“处理中…”状态；骨架不使用流光。
- Hover 不让卡片大幅上浮；确需浮起时位移不超过 2px，且只用于明确可点击对象。
- 支持 `prefers-reduced-motion` 关闭非必要动画；该媒体查询只控制动效，不改变颜色主题。

## 14. 响应式规则

后台系统以桌面端为主，覆盖常规办公电脑、小尺寸笔记本、大屏显示器和平板横屏。

### 14.1 内容宽度与留白

- 常规页面内容最大宽度：1440px，水平居中。
- 代码 Diff、全量表格等工作台页面可放宽至 1680px，或在主导航后占满可用宽度。
- 视口 ≥ 1440px：页面左右留白 32–40px。
- 视口 1200–1439px：页面左右留白 24–32px。
- 视口 960–1199px：页面左右留白 20–24px。
- 视口 768–959px：页面左右留白 16–20px。
- 内容区不得依赖固定宽度；使用弹性网格和最小/最大约束。

### 14.2 布局降级

- ≥ 1200px：完整导航；2–4 列数据卡片按内容宽度自适应。
- 960–1199px：导航可收为窄栏；4 列卡片降为 2 列。
- 768–959px：导航默认折叠或以抽屉打开；多列内容降为 1–2 列。
- 平板横屏优先保留主内容和审核操作，次要元数据可折叠。
- 不以缩小字号解决空间不足；优先换行、折叠次要操作、减少列数。
- 表格在自身容器横向滚动，并固定首个识别列和必要操作列。
- 筛选栏空间不足时先换行，再将低频条件收进“更多筛选”。
- 弹窗最大宽度不超过视口减 32px；长内容优先改用抽屉或页面。

## 15. 浅色主题规则

- 系统当前且仅设计浅色主题，页面始终保持浅色模式。
- 不使用 `prefers-color-scheme: dark` 自动改变颜色。
- `prefers-color-scheme` 仅可用于识别，不得触发主题切换；`prefers-reduced-motion` 可用于减少动效。
- 应声明页面和原生控件采用浅色配色，使浏览器或操作系统暗黑模式不改变表单、滚动条或原生控件的核心视觉。
- 新增或改版页面不得添加 `html.dark`、暗色 Token 分支或暗色专属资源。
- 现有暗色相关代码视为历史实现，不是本文主题来源；未经独立需求不得扩展，也不在本次规则任务中清理。
- 当前阶段不设计暗色主题，不为“以后可能需要”预留未经验证的暗色颜色。

## 16. 禁止使用的设计形式

- 大面积霓虹渐变、蓝紫色 AI 光效、发光线条、粒子和星空；
- 机器人、大脑、芯片电路、数据流、虚拟人物等典型 AI 元素；
- 玻璃拟态滥用、全局毛玻璃导航和大面积透明卡片；
- 大面积高饱和色、传统企业后台深蓝主题；
- 重边框、重阴影、密集网格线和重复分割线；
- 为体现科技感堆叠无业务价值的装饰；
- 所有组件统一大圆角、所有标签胶囊化；
- 普通按钮和内容卡片使用渐变；
- 每张卡片独立配色、彩色标签墙；
- 持续呼吸、弹跳、旋转、流光或循环装饰动画；
- 通过大量粗体、全大写英文和过宽字间距制造层级；
- 用绿色覆盖整片代码、Diff、表格表头或页面背景；
- 为主题统一而改动业务逻辑、页面结构或引入新依赖。
