# 交付规则

## 开发准入

单项功能进入编码前必须明确：

- 对应产品路线图的业务模块和阶段；
- 触发者、主流程、失败流程和本次非范围；
- 所需数据对象、状态、接口、权限和外部副作用；
- 幂等与重试边界；
- 可自动或人工复现的验收步骤。

缺少以上内容时，先使用 `skills/plan-review-feature/` 补计划，不生成 CRUD 骨架。

## 数据与接口

- 数据表和脚本随真实功能切片设计，不提前发明迁移框架或批量预建表；
- 不直接改写已在共享环境执行的历史脚本；首次正式业务迁移时先确认仓库采用的脚本策略；
- 标识、唯一键、查询索引和数据保留期必须在功能方案中明确；
- 列表接口沿用 `TableDataInfo`，普通响应沿用 `AjaxResult`；
- Webhook 成功接收与审查最终成功是两个状态，不在请求线程等待完整审查流程。

## 安全与隐私

- 外部凭据必须加密存储、响应脱敏、日志隐藏；
- Webhook 必须具备签名验证、重放防护、载荷限制和事件去重；
- 仓库内容、Diff、Prompt、模型响应和审查结果按企业代码资产处理；
- 外部回写、通知和合并卡点等副作用必须记录请求标识、结果和可重试状态。

## 完成标准

- 后端测试与前端生产构建通过；
- 新增状态、幂等、失败重试和权限边界有相应验证；
- SQL 可按说明执行且不暴露密钥；
- 没有未使用的模板类、无效配置、构建产物或本机文件进入版本库；
- 文档中的范围、模块和目录与实际变更一致。
