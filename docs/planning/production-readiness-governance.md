# 正式上线前完整性治理（2026-08-12）

## 1. 结论与发布边界

本次以“对外承诺与实际能力一致”为目标，不扩建报告系统或消息中台。完成本次改动后，平台适合继续作为 **V0.2 核心版受控推广**：已交付的入口可用、未交付的报告入口不再伪装成正式能力、项目通知具备最低限度的降噪策略，生产运行依赖风险已显著下降。

平台仍**不满足 V1.0 企业正式使用准入**。统一身份或完整账号生命周期、业务审计导出、数据留存、备份恢复演练、不可变报告、订阅、Token/成本/配额事实以及 GitLab/Gitee/Gitea 真实环境闭环等企业级能力尚未完成，不应以文档规划替代交付验收。

## 2. 目标、范围与成功标准

### 2.1 本次范围

1. 隐藏并停用仅有占位页的“报告中心”，存量数据库与全量初始化口径一致；
2. 在现有“项目单渠道绑定”上增加结论策略与项目级冷却窗口，保留投递记录和补发机制；
3. 对前后端生产依赖的高危、中危问题按实际调用面处置，不进行无依据的大版本追新；
4. 将核心版、企业版和后续优化项按仓库真实能力重新标记。

### 2.2 明确不做

- 不建设多渠道编排、按人订阅、跨项目聚合任务、模板规则引擎或通用消息中台；
- 不实现仅有规划、尚无数据模型和验收条件的报告/订阅/成本模块；
- 不以大版本升级替代可利用性判断，不为清零扫描结果引入未经验证的兼容风险；
- 不把前端包体优化、更多 Provider 扩展混入本次 P0 收口。

### 2.3 成功标准

- 用户菜单不再出现看似可用但仅显示占位文案的报告功能；
- 新项目默认只通知风险结论，管理员可配置全部/风险/仅阻断与 0–1440 分钟冷却；
- BLOCK 和执行失败不受冷却抑制，被策略或频控抑制的事件仍以 `SKIPPED` 留痕；
- 前端生产依赖审计为 0；后端已知可直接利用的上传解析风险完成修复；
- 路线图明确区分“已实现”“仅契约测试”“企业版未交付”和“后续优化”。

## 3. 功能治理

### 3.1 报告中心

当前报告页没有报告快照、版本、生成、导出、订阅或发送记录数据模型，仅有占位组件。继续展示会让用户误判能力并产生正式使用预期，因此采用以下边界：

- 菜单 `134` 设为隐藏且停用；
- 全量初始化和存量升级脚本采用相同状态；
- 保留路由组件作为旧数据库或直接 URL 的兜底，仅明确显示“企业版尚未开放”；
- 仅当不可变快照、权限隔离、导出审计、订阅和发送记录完成验收后重新开放。

这不是删除规划能力，而是把未交付能力从正式产品界面撤回到企业版路线图。

### 3.2 通知最小策略

仍保持“一个项目绑定一个群机器人渠道”，避免扩大渠道模型。新增两个项目级字段：

| 配置 | 取值/范围 | 行为 |
|---|---|---|
| 结论策略 | `ALL` | PASS、WARN、BLOCK 均通知；存量项目默认值，保证升级行为不突变 |
| 结论策略 | `RISK_ONLY` | 仅 WARN、BLOCK 通知；新项目默认值 |
| 结论策略 | `BLOCK_ONLY` | 仅 BLOCK 通知 |
| 冷却窗口 | 0–1440 分钟 | 同项目同渠道在窗口内已有待处理或成功投递时，抑制后续 PASS/WARN；失败投递不计入 |

执行失败仍由原有“失败时通知”开关控制；BLOCK 和执行失败始终绕过冷却。策略或频控命中后不调用外部渠道，但写入 `review_delivery_record` 的 `SKIPPED` 记录及稳定错误码，便于运营核查。手动补发沿用现有投递记录流程，不新增队列或聚合表。

权限边界沿用项目治理模型：项目通知策略由项目配置权限与项目角色共同约束；通知渠道本身仍是平台级敏感资产，普通项目角色只能引用已启用渠道，不能查看或管理 Webhook 密文。

## 4. 依赖风险处置

审计日期为 2026-08-12。评估同时考虑依赖是否进入生产包、系统是否使用相关功能、攻击者能否控制输入以及升级兼容风险。

### 4.1 已处理

| 依赖/风险面 | 实际可利用性 | 处置 | 兼容判断 |
|---|---|---|---|
| Apache POI 4.1.2 / OOXML 重复条目解析 | **可利用**：系统存在登录用户上传 Excel 的导入接口，攻击者可控制工作簿 | 升级到首个修复版本 5.4.0；同时消除旧 `commons-compress` 高危归档解析链 | POI 主 API 基本兼容，必须由导入单测与完整后端测试验证 |
| Spring Boot 4.0.3 管理的 Spring/Tomcat/Security 等运行依赖 | Web 服务、认证和序列化均直接使用，不能按“间接依赖”忽略 | 升级到同一 4.0 线最新补丁 4.0.7，不跨 4.1 | 补丁升级优先，避免框架次版本迁移 |
| Axios 1.13.2、js-cookie 3.0.5 | 浏览器请求与 Token/Cookie 管理直接使用，原型污染/XSRF 等风险与登录态相关 | 分别升级到 1.18.0、3.0.8 | 保持现有公开 API |
| ECharts 5.6.0 | 看板字段含项目、系统和成员名称，存在被污染数据进入图表渲染面的可能 | 升级到 6.1.0 | 属主版本升级，须以生产构建和看板浏览验证兜底 |
| form-data、postcss、nanoid、Vite、braces/micromatch、brace-expansion、immutable、svgo | 部分仅构建期可达，仍可能影响 CI 或构建产物完整性 | 升级/覆盖到扫描建议的修复版本 | 不改变业务代码接口，生产构建验证 |

处置后 `npm audit --omit=dev` 为 0 个漏洞。

### 4.2 风险接受与后续计划

| 残余项 | 当前暴露面与结论 | 风险接受条件 | 后续计划 |
|---|---|---|---|
| `vite-plugin-svg-icons → svg-baker → image-size` 两项高危无限循环 | 仅在前端构建期扫描仓库内 `src/assets/icons/svg`；运行时不接收或解析用户图片。上游当前无修复版本，盲目降级插件会引入兼容倒退 | 仅允许受代码审查的仓库 SVG 进入图标目录；CI 不从外部下载 SVG；不把该链路放入在线转换服务 | 上游发布修复后升级；若长期无修复，替换 SVG 打包插件并做图标回归。该风险不进入浏览器生产包 |
| Jackson 3.1.4 / 2.21.4 的 `JsonView`/反序列化授权绕过类中危公告 | 仓库未使用 `@JsonView`、`@JsonUnwrapped`、外部类型 ID或大小写不敏感反序列化，当前无依赖这些机制实现写权限的接口，实际利用前提不成立 | 不新增以 Jackson 注解代替服务层授权的写接口；保持 DTO 白名单与服务层权限校验 | 跟随 Spring Boot 4.0.x 后续补丁统一升级到 Jackson 3.1.5/2.21.5 或更高修复版，避免手工混用 BOM |
| Netty DNS 4.2.15 内存泄漏中危公告 | 仅 Redis/Lettuce 等客户端 DNS 解析链可能到达；利用需要攻击者向运行环境注入恶意 DNS 响应，公网接口不能直接触发 | 生产 DNS 可信且网络隔离；Redis 使用受控地址；监控进程内存与 Redis 连接异常 | 跟随 Boot 补丁升级至 Netty 4.2.16+；如部署模型必须解析不可信 DNS，则上线前单独覆盖整套 Netty BOM 并回归 |

上述残余项均不能作为“零风险”表述。若企业上线环境不满足风险接受条件，应阻断发布并提前完成依赖替换或整套 BOM 升级。

## 6. 发布门槛建议

### 核心版（V0.2，受控推广）

- 本次 SQL 迁移、后端测试、前端生产构建和生产依赖审计全部通过；
- 仅向试点组织开放，使用 GitHub 已验收链路；其他 Provider 明确标记待真实环境验收；
- 生产环境落实数据库和文件备份的临时人工方案，并指定风险接受责任人；
- 不展示报告中心，不宣传统一身份、不可变报告、订阅或成本治理。

### 企业版（V1.0，内部正式使用）

以下为准入项，而非可选优化：统一身份或完整账号生命周期、业务审计导出、数据留存、备份恢复演练、不可变报告与受控导出、Token/调用量基础归集和配额提醒、目标 Git Provider 真实闭环、权限抽查及业务 SLI 验收。

### 后续优化

前端分包和资源预算、复杂聚合通知、更多渠道、强成本预算、跨团队对比、SARIF 等在有真实指标和场景后单独立项，不阻塞本次核心版收口。
