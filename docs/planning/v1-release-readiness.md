## 本次范围与成功标准

- 说明、示例和计量单位保留必要技术原名；后台文案对照稿定稿，第三方数据监控按用户要求排除。
- 中英文 README 介绍一致，只列已交付能力，安装步骤与当前镜像一致。
- Compose 网页入口能够将 `/webhook/{provider}` 转发至后端，保留请求路径、签名头和原始请求体。
- 停用、删除或重置密码后的旧登录会话不能继续访问；账号重新启用不能让旧会话复活。
- 指标名称及帮助说明准确表达各项目每日成功任务 P95 的最大值，计算方法保持原样。
- 后端测试、前端单测、生产构建和 Compose 配置检查通过；未进行的现场验证单独列明。

主要业务仍位于 `acr-review`，账号治理位于 `acr-system`，认证位于 `acr-framework`。本次不引入新框架、业务表或 SQL 迁移；未交付报告入口继续隐藏。文案稿为原文对照，除本次单独修正的耗时指标外，不批量更改页面功能或文案。

## 企业部署验收条件

- 入口启用 HTTPS，Webhook 与详情链接分别从代码平台和团队网络可达。
- 使用独立 JWT、数据库与 Redis 密钥，数据库账号按最小权限授权；首次登录修改管理员密码。
- 模型和网络地址属于允许范围，明确代码上下文的外发与保留规则。
- 备份数据库、上传文件和凭据主密钥，在隔离环境验证恢复并记录 RPO/RTO。
- 对计划使用的 Git 实例、模型和通知渠道验证接入、检查、回写、通知及问题复核；GitLab/Gitee/Gitea 契约测试不能代替实际实例验证。
- 验证账号与项目授权、指标口径、容量、失败恢复与值守安排。

这些条件由部署方在自己的环境完成。仓库测试、容器健康和软件版本号不能替代现场验收。

## 账号安全变更的运行影响

认证时定点核对当前账号状态和会话版本，登录时核对认证期间的账号变化；数据库或 Redis 无法核实时拒绝沿用缓存身份。账号安全变更更新会话版本，旧会话即使被并发续期也不能恢复有效；不逐请求扫描在线会话。

每个已登录请求增加一次账号查询和一次会话版本读取，需要纳入部署容量验证。会话版本键不得单独过期或清理；若清空该命名空间，必须同时清空所有登录会话。升级无需改表，账号停用、删除和密码变更会要求受影响用户重新登录。
