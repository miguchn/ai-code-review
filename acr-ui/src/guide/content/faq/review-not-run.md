# 审查没执行或结果不符预期

这篇帮你处理三类问题：PR 之后没有审查任务、任务执行失败、审查结论不符合预期。

## 情况 1：发起 PR 后没有任何任务

先确认 Webhook 链路是否打通，按「常见问题 → Webhook 没触发怎么办」排查；确认任务列表本身没有遗漏筛选条件（「审查中心 → 审查任务」清空筛选后刷新）。

## 情况 2：任务失败或长时间不结束

进入「审查中心 → 审查任务」，结合「任务状态」「当前步骤」「失败原因」三列定位。

任务状态流转：**待执行 → 执行中 → 已完成 / 已失败**（已取消为人工操作）。当前步骤依次为：解析配置 → 准备工作区 → 调用大模型 / 调用审查引擎 → 保存结果。「失败原因」列展示具体描述文本，按下表对号入座：

| 失败原因的含义 | 常见原因 | 处理 |
|---|---|---|
| 提示配置缺失（如「审查引擎需要平台默认模型作为运行时模型，请先在「模型服务」配置并启用默认模型」「不支持的审查方式」） | 模型/模板未启用、审查方式配置不全 | 检查项目审查方式配置；引擎方式需先在「策略配置 → 大模型配置」设置已启用的默认模型 |
| 提示凭据错误 | 令牌过期或权限不足 | 「项目接入 → 访问凭据」更新 Token 并点「检测」 |
| 停在「准备工作区」或提示工作区/仓库拉取失败 | 凭据无仓库权限、仓库过大、网络不通 | 核对凭据权限与仓库地址；大仓库适当放宽后端拉取超时 |
| 提示超时 | 模型或引擎调用超时 | 调大模型配置的「超时(ms)」；引擎侧调整 `ACR_OCR_TIMEOUT_SECONDS` |
| 提示模型调用失败 | 模型服务报错 | 先在「策略配置 → 大模型配置」做检测，按「模型与引擎 → 模型检测失败排查」处理 |
| 提示引擎执行失败 | CLI 执行异常 | 「策略配置 → 审查引擎」查看环境检测与最近测试，对照失败类型处理 |
| 提示速率限制 / 并发超限 | 厂商限流或引擎并发打满 | 稍后重试；并发可调整 `ACR_OCR_MAX_CONCURRENCY` |
| 提示结果格式非法 | 模型输出不符合解析协议 | 先重试；反复出现时更换模型或审查模板 |

修复原因后，点击任务行的「重试」（待执行任务显示为「执行」）重新执行。

## 情况 3：结论不符合预期

- **改了模板但旧任务没变化**：任务创建时会冻结当时的审查模板、模型配置与审查范围快照，之后修改模板只影响新建任务；重试沿用原快照。要让旧 PR 用新模板，向 PR 再推一次提交（触发新事件建新任务）；
- **历史存量问题没有被指出**：平台默认只审查本次合并请求变更的内容，不扫描整个文件的历史问题，存量问题不打标上报——这是默认策略，不是漏审；
- **部分文件没有被审查**：检查项目「审查范围」页签的排除路径、是否关闭了「审查测试文件」；锁文件、依赖目录与构建产物由平台统一排除；「高影响扩展」开启时，新增文件、签名变更等会自动扩展为整文件审查；
- **结论等级疑问**：结论分为 通过 / 建议修改 / 高风险，由问题严重度与数量评定；到「审查中心 → 审查记录」查看评分与问题明细，问题可在「问题台账」跟踪处置。

## 接入前预防

新接入项目前，建议先完成两项检测：模型配置页的「连接测试 + 模型调用测试」、审查引擎页的「环境检测 + 测试调用」（引擎方式），再接入仓库。
