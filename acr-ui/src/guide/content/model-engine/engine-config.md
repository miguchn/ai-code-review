# 审查引擎配置

这篇帮你理解本地审查引擎（open-code-review）的配置项、检测方式，以及它与「大模型审查」怎么选。

## 适用场景

审查引擎方式由平台在本机调用 open-code-review CLI 完成审查，适合：

- 希望审查执行过程与规则扩展统一收口在引擎侧的团队；
- 需要结合引擎内置规则做检查的场景。

注意：引擎执行时仍会调用模型——使用平台默认模型作为运行时模型。完全离线环境需将内网自建模型服务配置为默认模型（见「模型与引擎 → 模型服务配置」）。

## 配置来源

「策略配置 → 审查引擎」页面为**只读展示页**，配置来自后端部署参数（环境变量），不在页面编辑：

| 页面字段 | 含义 | 默认值 / 对应环境变量 |
|---|---|---|
| 引擎名称 | 引擎显示名 | open-code-review |
| 引擎类型 | 调用形态 | LOCAL_CLI（本机命令行） |
| 可执行文件 | CLI 路径或命令名（需在 PATH 中） | `ocr`（`ACR_OCR_EXECUTABLE` 可覆盖为绝对路径） |
| 工作目录根路径 | 每次调用在其下创建独立子目录 | 系统临时目录下 `acr-review-engine`（`ACR_OCR_WORKSPACE_ROOT`） |
| 默认超时 | 单次引擎调用超时 | 600 秒（`ACR_OCR_TIMEOUT_SECONDS`） |
| 最大并发 | 同时执行的引擎调用数 | 2（`ACR_OCR_MAX_CONCURRENCY`） |
| 输出上限 | stdout/stderr 单次读取上限 | 1 MB（`ACR_OCR_MAX_OUTPUT_BYTES`） |
| 当前版本 / 可用状态 | 由「环境检测」刷新 | — |
| 最近检测 / 最近测试 | 最近一次环境检测与测试调用的结果和时间 | — |

修改这些参数需调整后端环境变量并重启服务。

## 环境检测与测试调用

页面右上角两个按钮：

1. **环境检测**：探测可执行文件是否存在、可运行，刷新「当前版本」与「可用状态」。检测失败常见类型：CLI 不存在、权限不足；
2. **测试调用**：使用内置样例仓库跑一次真实调用（**不会读取用户代码**），需选择一个已启用的模型配置（默认选中平台默认模型）。结果区展示是否成功、耗时、退出码、失败类型及 stdout/stderr。

常见失败类型对照：

| 失败类型 | 处理方向 |
|---|---|
| CLI 不存在 | 安装 open-code-review，或设置 `ACR_OCR_EXECUTABLE` 为绝对路径 |
| 权限不足 | 给可执行文件加执行权限，或调整部署账号 |
| 工作目录错误 | 检查根路径是否存在、可写 |
| 执行超时 | 调大 `ACR_OCR_TIMEOUT_SECONDS` |
| 模型调用失败 | 先排查默认模型：见「模型与引擎 → 模型检测失败排查」 |
| 退出码异常 / 输出格式错误 | 查看结果区 stderr 定位引擎侧问题 |
| 并发超限 | 等待或调大 `ACR_OCR_MAX_CONCURRENCY` |

## 与「大模型审查」怎么选

项目的「审查方式」提供二选一：

- **大模型审查**：平台直接调用模型审查本次 PR 的变更，配置简单（选模型 + 审查模板），大多数团队的首选；
- **审查引擎**：平台调用本地 open-code-review 引擎，需部署 CLI 且必须配置平台默认模型；当前仅支持 open-code-review 一种引擎。

已接入项目要切换方式：编辑项目 →「审查方式」改选后保存；方式的切换只影响之后新建的审查任务。
