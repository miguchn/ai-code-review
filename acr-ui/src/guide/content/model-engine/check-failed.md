# 模型检测失败排查

这篇帮你按「最近检测结果」显示的错误类型定位模型配置问题：网络、密钥、模型名、额度四类原因逐一排查。

## 如何读取检测结果

检测入口：「策略配置 → 大模型配置」→ 编辑某条配置 →「连接测试」或「模型调用测试」。结果弹窗展示时延、错误类型、错误信息与响应摘要，同时写回模型列表的「最近检测结果」列，格式为「错误类型: 具体原因」，如：

- 成功：`成功 (820ms)`
- 失败：`认证失败: ...` / `模型不存在: ...` / `请求超时: ...`

对照下面的分支处理。

## 分支 1：网络错误 / 请求超时 / 地址错误（服务不可达）

**检查动作**：

1. API 地址是否完整正确——必须包含完整路径（如 `/v1/chat/completions`），不是厂商首页地址；
2. 在平台部署服务器上执行 `curl -sS -o /dev/null -w "%{http_code}" <API地址>`，确认出网可达（内网环境常因无外网出口而超时）；
3. 协议与端口是否匹配（HTTPS/HTTP、代理端口）。

**修复动作**：

- 地址错误：修正为厂商文档的 Chat Completions 地址（各厂商参考见「模型与引擎 → 模型服务配置」）；
- 内网无出口：申请外网代理/专线，或改用内网自建模型服务（服务厂商选「其他/自定义」）后重新检测。

## 分支 2：认证失败（API Key 问题）

**检查动作**：

1. API Key 是否复制完整（常见首尾空格、漏字符）；
2. Key 是否已在厂商控制台被禁用、删除或过期；
3. Key 是否属于当前选择的厂商与账号（不同厂商的 Key 不通用）。

**修复动作**：到厂商控制台重新生成 Key，粘贴到配置中保存（编辑时 Key 输入框留空表示保留原值，换 Key 必须重新填写），再点「连接测试」。

## 分支 3：模型不存在（模型标识问题）

**检查动作**：

1. 「模型标识」拼写是否与厂商文档一致（如 `deepseek-chat`，区分大小写与连字符）；
2. 该模型是否已下线或改名；
3. 你的 Key/账号是否已开通该模型的调用权限（部分模型需单独申请）。

**修复动作**：改为厂商文档中当前可用的模型标识，保存后点「模型调用测试」验证。

## 分支 4：速率限制（额度或限流）

**检查动作**：

1. 厂商控制台查看账户余额、免费额度是否用尽；
2. 是否短时间内多个项目共用同一 Key 高频调用触发限流。

**修复动作**：充值/续期额度；错峰重试；为不同项目配置不同 Key；持续限流时联系厂商提升配额。

## 仍无法解决

- 「连接测试」通过但「模型调用测试」失败：多为模型标识或参数（最大 Token、上下文长度）不匹配，按分支 3 处理；
- 「未知错误」：查看结果弹窗的「摘要」原始响应片段，通常包含厂商返回的具体报错；
- 检测均正常但审查任务仍失败：问题可能不在模型配置，见「常见问题 → 审查没执行或结果不符预期」。
